# C2-Pay · ระบบเบิกจ่าย C2 Tech

หน้าเว็บ (GitHub Pages) ของระบบเบิกจ่าย · backend อยู่ที่ `C:\dev\c2-pay-firebase` (Cloud Functions codebase `pay`)

## โครงสร้าง
- อยู่ใน Firebase โปรเจกต์เดียวกับ C2-Calendar (`c2-calendar-c088f`) เพื่อใช้ **บัญชี login ชุดเดียวกัน**
- เข้าระบบ: เรียกฟังก์ชัน `login` ของ C2-Calendar → ได้ token → ทุกคำสั่งของ C2-Pay ส่งผ่านฟังก์ชัน `payApi`
- ข้อมูล C2-Pay อยู่ใน collection ที่ขึ้นต้นด้วย `pay_` และไฟล์ใน Storage โฟลเดอร์ `pay/` — หน้าเว็บอ่าน/เขียน Firestore ตรงไม่ได้ (firestore.rules ของ C2-Calendar ปิดไว้อยู่แล้ว)
- สิทธิ์ C2-Pay ตั้งแยกจาก C2-Calendar: Admin / CEO / User / ไม่มีสิทธิ์
  - ค่าเริ่มต้นบัญชีใหม่: staff → User, ceo → CEO, admin → User (Admin ของ C2-Pay ต้องตั้งเองรายคน · ต้องมี Admin อย่างน้อย 1 คน)
- **ผู้ดูแลเลขบัญชี** มีได้คนเดียว: เพิ่ม/แก้เลขบัญชีรับโอนของทุกคนและบัญชีบริษัท · ต้องใส่รหัสผ่านซ้ำ + เหตุผล · มีประวัติที่ลบไม่ได้ · แจ้งเจ้าของบัญชี · Admin คนอื่นเห็นเลขแบบปิดบางส่วน
- **โหมดทดลองใช้**: ผู้ดูแลเลขบัญชีล้างข้อมูลได้ (แบบ A รายการเงิน / แบบ B ทุกอย่าง) ต้องดาวน์โหลดไฟล์สำรองก่อน + พิมพ์ "ล้างข้อมูล C2-Pay" + รหัสผ่าน + รอ 5 วินาที · กด "ปิดโหมดทดลอง" แล้วเมนูนี้หายถาวร

## เริ่มใช้ครั้งแรก
1. deploy backend (ดู README ใน `C:\dev\c2-pay-firebase`)
2. เปิดหน้าเว็บ → admin ของ C2-Calendar คนแรกที่เข้า จะเห็นหน้า "ตั้งค่าเริ่มต้น C2-Pay" → ยืนยันรหัสผ่าน → เป็น Admin + ผู้ดูแลเลขบัญชี
3. ตั้งค่า → ผู้ใช้และเลขบัญชี: ตั้งสิทธิ์ทีมงาน และเพิ่มเลขบัญชีรับโอน

## รอบการพัฒนา
- [x] รอบ 1 (2 พ.ย. 2569): เข้าระบบ · สิทธิ์ · ตั้งค่า · เลขบัญชี · โหมดทดลองใช้
- [x] รอบ 2 (2 พ.ย. 2569): ใบเบิกค่าเดินทาง — ขอเบิก → อนุมัติ (เงินสดย่อย/รอโอน) → บันทึกโอน+สลิป → ส่งเคลียร์ → ยืนยัน → คืนเงิน/จ่ายส่วนต่าง → ปิดใบ
  - ระยะทาง: OpenRouteService จากพิกัดจุดเริ่มต้นและลูกค้า (ตั้งคีย์ที่ ตั้งค่า → ค่าทั่วไป) · แก้ระยะเองต้องใส่เหตุผล
  - เคลียร์: ที่พักคืนไม่เกินราคาที่อนุมัติ · ค่าใช้จ่ายอื่นต้องมีใบเสร็จ (หรือเหตุผล) · ส่วนเกิน admin อนุมัติได้
  - สถานะเคลียร์ตามกฎ 3/5/7 วัน (ตั้งได้ใน ค่าทั่วไป) · โอนครั้งแรกหลังเปลี่ยนเลขบัญชีต้องยืนยันกับเจ้าตัว
  - เงินสดย่อย: ยอดคงเหลือ + เติมเงิน (หน้าเต็มรอบ 3) · ปิดใบแล้วลงสมุดค่าใช้จ่ายอัตโนมัติ
  - ยังไม่มี: ต่อทริป, ใบเสนอ CEO (รอบ 4)
- [x] รอบ 3 (3 พ.ย. 2569): สร้างใบใหม่ ADV / RMB / EXP · เคลียร์เงินทดรอง · สมุดค่าใช้จ่าย · เงินสดย่อยเต็ม
  - เงินทดรอง (ADV): ใส่รายการ + ยอดประมาณ → จ่ายเงินสดย่อย/โอน → เคลียร์ด้วยใบเสร็จ (ไม่มีใบเสร็จต้องใส่เหตุผล) → คืน/จ่ายเพิ่ม/ปิด
  - เบิกคืน (RMB): บันทึกใบเสร็จที่ทีมงานสำรองจ่าย → จ่ายคืนเงินสดย่อย (ปิดทันที) หรือโอน (เข้ารายการรอโอน)
  - ค่าใช้จ่ายบริษัท (EXP): เงินสดย่อย = ลงสมุดทันที · โอน = รอโอน ลงสมุดเมื่อแนบสลิป
  - สมุดค่าใช้จ่าย: กรองเดือน / หมวด / ที่มาเงิน · สรุปตามหมวด · ส่งออก Excel
  - เงินสดย่อย: ตารางเข้า-ออกพร้อมยอดคงเหลือ · ใช้ไปตั้งแต่เติมครั้งก่อน · ตรวจนับ (ยอดไม่ตรงต้องใส่เหตุผล บันทึกเป็นรายการปรับยอด)
  - ทุกฟอร์ม: ช่องที่ยังไม่กรอกขึ้นกรอบแดง + ข้อความใต้ช่อง + แจ้ง "กรอกข้อมูลไม่ครบ: …" (เลขบัญชีตรวจ 10–15 หลัก · ไฟล์ HEIC ของ iPhone แจ้งให้แปลงก่อน)
- [x] รอบ 4 ส่วนที่ 1 (3 พ.ย. 2569): ใบเสนอ CEO (APV)
  - ทุกการโอนต้องผ่านใบเสนอ: เลือกรายการ → สร้างใบ → พิมพ์ A4 (หน้าสรุป + รายละเอียด) ให้ CEO เซ็น → แนบสแกน → ส่งเรื่องเข้าระบบธนาคาร → COO อนุมัติ → แนบสลิป → ใบเบิกเดินต่ออัตโนมัติ
  - CEO ไม่อนุมัติบางรายการได้ (ใส่สิ่งที่ให้แก้) · รายการกลับไปรอเข้าใบเสนอใหม่ · ยกเลิกทั้งใบได้ก่อนโอน
  - บัญชีที่เพิ่งเปลี่ยนต้องติ๊กยืนยันตอนสร้างใบ และพิมพ์หมายเหตุสีแดงในใบเสนอ
  - เลขบัญชีพิมพ์เต็มเฉพาะเมื่อผู้ดูแลเลขบัญชีพิมพ์ (คนอื่นเห็นแบบปิดบางส่วน)
  - เบิกชดเชยเงินสดย่อย: ส่งเข้าใบเสนอเดียวกัน · โอนแล้วเติมเงินสดย่อยอัตโนมัติ
